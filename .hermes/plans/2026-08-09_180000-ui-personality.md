> **Evidence reconciliation:** the research memo recommends "Warm Archivist" (A) as base, borrowing Terminal Detective's status glyphs and Indie Zine's marquee strip [R-7]; its one divergence from this plan is "keep the blue primary" — **superseded by the antislop finding** (blue hue ≈255 IS the generic-tech-hue tell, smell-report #2). Ink-green stands. All other memo moves (status dot + worded tooltip [R-1][R-24], `--font-heading`/`--font-mono` tokens already defined but unused [R-6], emoji accent system [R-5], graveyard styling [R-12], hero one-liner + live stats [R-1], signed footer [R-2]) are folded in below.

**Goal:** Give IdeaExists a distinctive, human personality without breaking its identity — local-first, verification-first, honest, one-pager warm-minimal. The current UI is functionally complete but visually generic (neutral zinc + template blue, zero motion, near-zero voice). Personality comes from **tokens, texture, type, microcopy, and micro-motion** — not a structural redesign.

**Direction (recommended): THE WARM ARCHIVE** — a human-curated ledger aesthetic. The core question "Does this startup exist?" is inherently curious; the app answers it like a diligent archivist: serif display for the question, mono ledger type for data, warm ink-green + amber palette, deterministic-hue initials, stamped Verified mark, dry-curator microcopy, and honesty (dead entries, "no tracking") worn as charm.

**Alternatives (scope dials):**
- **B — "Case File":** full detective metaphor (mono everywhere, evidence-tag statuses, stamp chrome). More gimmick risk; heavier.
- **C — "Minimal Wit":** keep all current tokens; ship only copy + avatars + motion. Smallest change, least distinct.

**Architecture:** Frontend-only, zero backend changes (additive, non-destructive, reversible — one commit to revert). All color/type changes live in CSS variables in `globals.css`; copy changes are strings; one new tiny client component (`Reveal`). **No new npm dependencies**: fonts via `next/font/google`, motion via CSS transitions + IntersectionObserver (SSR-safe, honors `prefers-reduced-motion`), count-up via rAF. No favicon fetching (privacy: local-first app must not leak lookups to third-party CDNs) — deterministic-hue initials instead.

**Stack:** Next.js 16 (App Router, webpack dev), Tailwind v4 (`@theme inline` in globals.css), shadcn/ui, lucide-react, tw-animate-css, Plus Jakarta Sans already loaded.

## Task 1: Design tokens (type + color + texture) — `globals.css`, `layout.tsx`

- Add fonts: `Fraunces` (variable, optical sizes; `--font-display`) + `JetBrains Mono` (`--font-mono`) in `layout.tsx`; map in `@theme inline` (`--font-display`, keep `--font-mono` working — currently points at geist-mono which isn't loaded).
- Palette as variables only: `--primary` → warm ink-green (light + dark variants, verify `--primary-foreground` contrast ≥4.5:1); add `--accent-warm` (amber) as a new token for hover warmth and highlights; warm-tilt the neutral greys (paper-light / warm-dark) in both themes; warm-tilt emerald/destructive status hues.
- Dot-grid background: `body`/`main` overlay via `background-image: radial-gradient(...)` at low opacity, both themes; keep `bg-background` behind it.
- Hero + section-header type: `font-display` serif for h1 and section titles, `clamp()` sizing; metadata/footers in mono (`font-mono`), 11–12px, `tabular-nums`.
- **QA:** computed-style check of both themes (contrast of primary/primary-foreground, new muted pairs, dot-grid visibility in dark); no component changes needed beyond classes that reference tokens; **verify the webfonts actually load** (document.fonts / computed family, not just the style value); colorblind simulation (deutan/protan/tritan) on the verified/dead/amber pairs — icons + labels must carry meaning without color.

## Task 2: Deterministic-hue avatars + status treatment — `components/startup-card.tsx` (and consumers)

- New pure helper `hueFromName(name)` (hash → 0–360) + `AvatarTone` style: `hsl(h 45% 40% / 0.14)` bg, `hsl(h 45% 30%)` fg in light; lighter fg in dark [R-21]. Applied in `initials`-rendering spots: card, detail modal header, similar rows, home strips.
- Keep size/shape/typography identical; only background/text color changes.
- **Status pill upgrade (the highest-ROI move [R-1][R-24]):** add a 6px status dot (emerald/red/grey) beside the label; wrap in shadcn `Tooltip` with worded copy — Verified: "A human checked this link on <date>. It's alive." (uses existing `verified_at`); Dead: "Checked 3 times, link dead each time. Filed, never deleted."; Unverified: "Not yet confirmed — treat with curiosity." (dot is `aria-hidden`, pill keeps its accessible name).
- **Graveyard styling:** replace plain `opacity-60` on dead cards with a sepia/desaturate treatment (`opacity-80` + `saturate-50` + hairline `border-dashed`? — keep it quiet, "filed" not "mocked" [R-12]); name keeps `line-through` off — dead ≠ worthless, archive styling only.
- **QA:** both themes; dot visible in both; equal card heights per row unchanged (measured); tooltip keyboard-focusable.

## Task 3: Micro-motion — new `components/reveal.tsx` + `app/page.tsx` wiring

- `Reveal`: client component wrapping children; IntersectionObserver (`once: true`, rootMargin "-40px") adds a `.is-revealed` class; CSS transitions `opacity` + `translate` only; `@media (prefers-reduced-motion: reduce)` → opacity-only, no translate; content visible before JS (start-visible, animate only when observed — SSR-safe, no hydration mismatch).
- Stagger: pass `delay` prop (40–80ms × index) or set via inline style; apply to home strips + card grid (cap stagger at ~6–8 items, group the rest).
- Card hover: `hover:-translate-y-0.5` + border tint + shadow (150–200ms, `transition-transform`); press state `active:translate-y-0`.
- Verified pill: stamp-pop on mount — single ease-out scale 0.92→1 (cubic-bezier(0.22, 1, 0.36, 1), 200ms), once, motion-reduce safe. **No spring, no bounce** (antislop rule; overrides motion.md's spring allowance).
- Footer stats + "N startups" count: rAF count-up on first mount (400–600ms, ease-out), `tabular-nums`.
- **QA:** reduced-motion emulation shows content without transforms; no layout shift before/after reveal (getBoundingClientRect); with JS disabled all content visible.

## Risks / tradeoffs

- Serif display + ink-green is a taste call → mitigated by Open Questions + one-commit reversibility.
- Motion could feel gratuitous → spec-limited (reveal + feedback only, stagger caps, reduced-motion).
- Voice could read as jokey → restrained dry-warm default; every string trivially revertible.
- Fraunces at small sizes can look odd → display usage only (hero + section headers + modal name), body stays Plus Jakarta Sans.
