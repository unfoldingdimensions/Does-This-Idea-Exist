# Admin Seeder — Implementation Plan (batch-fetch famous startups, admin-gated)

> **For Hermes:** Use subagent-driven-development to implement this plan task-by-task (fresh subagent per task, spec-compliance then code-quality review). Read `backend/app/` and `frontend/lib/api.ts` first — this plan builds on the existing seed/dedup/verify architecture (plan `2026-08-09_010700-does-this-startup-exist.md`, Part 3).

**Goal:** Give the owner an admin-gated seeder in the website that batch-fetches famous/known startups from multiple sources (GitHub search, curated lists, pasted URLs) so the directory has real density for first-time users — with no full login system, just a secret token that knows it's the owner.

**Architecture:** A background-job seeder on the FastAPI backend. `POST /api/admin/seed` starts a daemon-thread job and returns a `job_id`; `GET /api/admin/seed/status/{id}` streams progress; the frontend polls it and renders a live progress bar. All sources funnel into the existing `enrich.seed_from_github` / `seed_from_website` (URL-dedup upsert + LLM profile + `verified=0`). Admin identity = single `ADMIN_TOKEN` from `backend/.env`, checked on `/api/admin/*` routes via an HMAC-constant-time FastAPI dependency. No accounts, no user table, no cookies — token lives in `sessionStorage` and rides the `X-Admin-Token` header.

**Tech Stack:** FastAPI (existing) + `threading` + GitHub Search REST API + opencode.go `deepseek-v4-flash` (existing LLM path) + shadcn/ui (existing frontend; add `progress`, `textarea`).

## Design decisions (sequential-thinking output)

| Decision | Choice | Why |
|---|---|---|
| Admin identity | `ADMIN_TOKEN` env var, `X-Admin-Token` header, `hmac.compare_digest` | "Knows it's me" with zero login system; **identical when hosted** — the env var lives on the host, the git-ignored `.env` never ships, and the token in `sessionStorage` travels with the browser; real auth is the documented upgrade if the site ever needs multi-user |
| Job model | POST returns `job_id` → daemon thread → status endpoint, polled every ~1.5s | Seeding takes minutes; user wants live progress (shadcn Progress + N/M counters) |
| Job storage | In-memory dict registry + console log | Single-user local app; no DB table (YAGNI; seed_log audit table is additive later) |
| Source 1 | GitHub Search API (`search/repositories`, sort by stars, `stars:>N` / topic filters) | Official, free, no ToS risk; one source pulls most famous OSS-backed startups |
| Source 2 | URL list (admin pastes website/github URLs) | Reuses existing seed paths; works from any external list/competitor scan |
| Source 3 | Bundled `data/seed_famous.json` (~60 hand-curated well-known startups) | The "initial incentive" set; one-click seed on first deploy |
| Source 4 | Product Hunt official API | Needs API key — **skipped for now** (open question) |
| Never | Scrape YC / Crunchbase | Established ToS decision from the original plan |
| Cost control | Per-run `cap` — **free-form input in the UI, default 30, no hidden ceiling** (testing can pull 100+ in one run); server validates `1..500` and returns a loud 400 outside that (never silent clamping); `reuse_profile=true` (default: skip LLM call when URL already in DB — re-runs are cheap + idempotent) | opencode.go plan has dollar caps ($12/5h, $30/wk) — the cap input is the owner's dial |
| Failure policy | **Fail loudly.** No bare `except: pass` on seed paths; every failure is logged (`logging.getLogger("ideasexist")`), recorded in `job["errors"]`, surfaced in the UI (red "N failed" badge + error list + summary toast). Rate-limit/LLM/404 errors are per-entry failures, never swallowed. `reuse_profile` skip is logged, not silent | The seeder reports truth; a "done" with failures reads as done-with-failures, never clean |
| Rate control | ~1s throttle between GitHub calls; search `per_page ≤ 20`; warn that batches >50 need `GITHUB_TOKEN` in `backend/.env` | unauth GitHub = 60 repo/hr, 10 search/min |
| Integrity | Seeded entries land `verified=0` → human "Mark verified" gate stays; URL-dedup upsert unchanged; failures collected, job never aborts | Directory never silently lies; re-seeding is safe |

```python
# config.py
ADMIN_TOKEN = os.getenv("ADMIN_TOKEN", "")

# main.py
import hmac

def require_admin(x_admin_token: str | None = Header(default=None)) -> None:
    if not config.ADMIN_TOKEN:
        raise HTTPException(403, "Admin disabled — set ADMIN_TOKEN in backend/.env")
    if not x_admin_token or not hmac.compare_digest(x_admin_token, config.ADMIN_TOKEN):
        raise HTTPException(403, "Invalid admin token")

admin = APIRouter(prefix="/api/admin", dependencies=[Depends(require_admin)])

@admin.get("/check")          # 200 {"ok": true} — used by the unlock dialog (loud: 403 otherwise)
def admin_check() -> dict: return {"ok": True}
```

**Step 2 — implement (`backend/app/seeder.py`, core shape):**
```python
import threading, time, uuid
from dataclasses import dataclass, field

JOBS: dict[str, dict] = {}
_LOCK = threading.Lock()

def start_job(source: str, params: dict) -> str:
    job = {"id": uuid.uuid4().hex[:12], "source": source, "params": params,
           "status": "queued", "total": 0, "done": 0, "ok": 0, "failed": 0,
           "errors": [], "current": "", "started_at": None, "finished_at": None}
    with _LOCK:
        JOBS[job["id"]] = job
    threading.Thread(target=_run, args=(job,), daemon=True).start()
    return job["id"]

def _run(job: dict) -> None:
    job["status"] = "running"; job["started_at"] = time.time()
    try:
        producer = SOURCES[job["source"]]          # yields candidate URLs/repos
        cap = int(job["params"].get("cap", 20))
        for i, candidate in enumerate(producer(job["params"])):
            if i >= cap: break
            job["total"] = min(i + 1, cap); job["current"] = str(candidate)
            try:
                _ingest(candidate, job["params"])  # -> enrich.seed_from_* (+ reuse_profile)
                job["ok"] += 1
            except Exception as exc:
                job["failed"] += 1; job["errors"].append(f"{candidate}: {exc}")
            job["done"] += 1
        job["status"] = "done"
    except Exception as exc:
        job["status"] = "failed"; job["errors"].append(f"job: {exc}")
    finally:
        job["finished_at"] = time.time()

def get_job(job_id: str) -> dict | None:
    with _LOCK:
        return JOBS.get(job_id)
```

**Step 3 — endpoints (`main.py`):**
```python
@admin.post("/seed")
def start_seed(body: SeedIn) -> dict:
    return {"job_id": seeder.start_job(body.source, body.params)}

@admin.get("/seed/status/{job_id}")
def seed_status(job_id: str) -> dict:
```

## Risks / Tradeoffs / Open Questions

**Risks:**
1. **LLM cost spikes** — dollar-capped plan; mitigated by `cap` default 20 + `reuse_profile` (re-runs cost nothing).
2. **GitHub rate limits** — unauth 60 repo/hr; batches >50 need `GITHUB_TOKEN` (env already supported). UI + README warn.
3. **Seeder quality** — auto profiles are LLM-drafted; human "Mark verified" gate stays; failures collected not fatal.
4. **Thread-safety** — single daemon thread per job, registry guarded by a lock; local single-user so no concurrency pressure.
5. **Token exposure** — plaintext in `.env` + `sessionStorage`; acceptable for localhost; real auth is the documented upgrade if the site goes public.

**Open questions (defaults in bold):**
- Q1 Progress transport: **polling every 1.5s** vs SSE (additive later; the `fastapi-sse-backends` skill exists if wanted).
- Q2 Batch cap: **20** (raise per run in UI).
- Q3 Famous list size: **~60 entries** (file is editable — user can trim/extend).
- Q4 Auto-verify seeded entries: **No — stays unverified**, human gate (default preserves trust).
- Q5 Product Hunt source: **skip** (needs API key; add later as a 4th producer).
- Q6 Admin UX: single token unlock (default) vs per-session re-entry — sessionStorage means re-entry per tab anyway.

**Definition of done:** owner opens the site → Admin → unlocks with their token → picks "Famous list" → watches progress → the directory jumps from 7 to ~60+ entries, all unverified and reviewable — and any re-run is idempotent and near-free.
