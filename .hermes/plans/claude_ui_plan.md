## Context

Two things prompted this part. First, the app's personality lives almost entirely in its **words** ("Dead is a status, not an erasure"), while the visual layer is comparatively inert — the audit found the FilterBar never signals an active filter, skeletons are six grey blocks standing in for a 24-card grid, the hero never animates in, and `design.json` documents an `entrance-stagger` token implemented nowhere. Second, two items were deliberately deferred from Part 1: the client-side-everything data path, and the Windows-only test runner with no CI.

**A prior review already exists and is absorbed here.** `.hermes/plans/2026-08-11_221500-ui-ux-review-liveliness.md` (untracked, 2026-08-11) contains a Playwright-measured issue inventory — M1–M4, L1–L8 — plus a live-QA script. Its findings are adopted below rather than re-derived. **What is superseded:** its motion philosophy ("without breaking the Warm Glass identity", no bounce, restrained). The design contract is now being deliberately loosened, so its R1–R10 recommendations are folded into a bolder direction.

**Decisions taken:** direction is **archival whimsy** (rubber stamps, card-catalog, ink, the Curator as a character) with **pervasive micro-delight** (many small moments, no set-pieces). `DESIGN.md` + `.impeccable/design.json` are amended to match, so this is an intentional contract change, not drift. Pagination is **guardrails, not pagination** (evidence below). Duplicates are **merged**, behind a backup and a dry-run report.

**Non-negotiable regardless of loosening:** status hues (sage/brick) stay reserved for status and always pair with a label or icon — colour-alone status signalling fails WCAG 1.4.1. All existing `prefers-reduced-motion` guards keep working.

## Phase 9 — Correctness and accessibility first

These are bugs, not polish. Ship before any visual work.

**Real bugs:**

1. **Pagination shows the wrong page.** [page.tsx:436](frontend/app/page.tsx:436) passes `page={page}` (unclamped) instead of `currentPage`. Verified failure: with `?page=40` and a filter yielding 3 pages, the grid correctly shows page 3 but the control renders no active pill and no `aria-current`, Next is disabled (`40 >= 3`), Prev appears dead, and clicking "3" is a no-op because `changePage` guards on `p === currentPage`. Fix by **renaming the prop** to `currentPage` in [continuous-pagination.tsx:13](frontend/components/ui/continuous-pagination.tsx:13) so TypeScript makes the mistake unrepeatable. Every other reader of `page` already goes through the clamp.
2. **`CountUp` has two bugs** ([count-up.tsx:22-37](frontend/components/count-up.tsx:22)) — it always restarts from 0 (verify one entry and the footer re-counts 0→95 instead of 94→95); and `if (reduce) return;` freezes the display at its mount value **forever**, so a reduced-motion user's counts never update. Track the previous value in a ref; make the reduced-motion branch `setDisplay(value)`.
3. **The detail modal's focus trap doesn't trap.** [startup-detail.tsx:43-59](frontend/components/startup-detail.tsx:43) restores focus correctly, but there is no Tab cycle — the prior review's live Tab trail walks out of the `aria-modal` dialog into the admin panel and `BODY` (WCAG 2.4.3), and because Escape is bound to the panel's `onKeyDown` ([:88](frontend/components/startup-detail.tsx:88)) it **stops working** once focus escapes, leaving the user stuck behind a click-blocking overlay. Add a Tab/Shift+Tab cycle plus a document-level Escape listener. (Part 1's claim that "the focus trap works" was about restore, not trapping — this is the more precise finding.)
4. **The "More" dropdown has no keyboard parity** ([morphing-discovery-bar.tsx:66-96](frontend/components/ui/morphing-discovery-bar.tsx:66)) — hover-gated open, no Escape, no arrow keys, no focus return (WCAG 2.1.1).
5. **Admin section toggle teleports** ([admin-panel.tsx:214](frontend/components/admin-panel.tsx:214)) — clicking an already-open header jumps to Seeding instead of collapsing. Allow `section === null`.
6. **Read-only status pill is keyboard-unreachable** ([startup-card.tsx:122-147](frontend/components/startup-card.tsx:122)) — a `span` as tooltip trigger, so the hint never appears for keyboard or touch users. Phase 10 reworks this into a popover, which fixes it properly.

**Honesty and correctness of what the UI claims:** 7. **Hero copy contradicts the trust legend.** [page.tsx:329](frontend/app/page.tsx:329) says "Every listing checked by a human, not a crawler" while the legend explains "Unverified — filed, awaiting a human" and only **317 of 1,292** are verified. For a trust product this is the one copy line that must not overclaim. Adopt "Kept by a human — checked one at a time." 8. **Sort select misrepresents ordering while searching** ([filter-bar.tsx:16](frontend/components/filter-bar.tsx:16) + [search.ts:148](frontend/lib/search.ts:148)) — results are relevance-ranked but the select reads "Top (stars)", and picking it is a no-op. Show a "Relevance" state while a query is active. 9. **"More like this" is not similarity** ([startup-detail.tsx:61-66](frontend/components/startup-detail.tsx:61)) — `filter(same category).slice(0,4)` returns the alphabetically-first four. Score by shared language / verified / tagline token overlap, tiebreak stars. 10. **Search isn't debounced despite the comment saying so** ([page.tsx:136](frontend/app/page.tsx:136), [search.ts:50](frontend/lib/search.ts:50)) — a fresh Fuse index is rebuilt over 1,292 rows on every keystroke; measured ~120–180ms added latency. Debounce ~150ms and memoise the Fuse instance per dataset. This also pushes out the ceiling in Phase 12 — **re-measure after this lands.** 11. **Mobile: the category row is 63px visible of 369px** at 375px ([morphing-discovery-bar.tsx:124](frontend/components/ui/morphing-discovery-bar.tsx:124)) — a core discovery surface effectively vanishes on phones. Stack below `sm`: search full-width, chips row full-width beneath. 12. **Card density** ([startup-card.tsx:255](frontend/components/startup-card.tsx:255)) — all 24 cards render "Show more" (every LLM description exceeds the 140-char threshold), giving three competing expand affordances. Raise to ~200 chars and clamp to 3 lines.

## Phase 10 — Archival whimsy, pervasive

Concrete mechanics. All transform/opacity/filter; no new dependencies.

**Motion foundations in use:**

- **Card "dealing"** — CSS-only `@keyframes deal-in` (opacity + `translateY(10px)` + alternating `rotate(±0.7deg)`), 380ms, `animation-delay: calc(var(--i) * 45ms)` capped at index 12, applied via a **wrapper div** in the grid at [page.tsx:427](frontend/app/page.tsx:427).
  > The class must go on a wrapper, not the card's own `motion.div`: CSS animations outrank inline styles, so it would suppress `whileHover` for 380ms and fight `layoutId` projection if the detail modal opens mid-animation.
  > **Remove `useAutoAnimate`** ([page.tsx:4,111,424](frontend/app/page.tsx:111)) — it animates inserts via WAAPI, which outranks CSS keyframes per-property and would produce a muddy double-fade with the transform silently dropped. One animation system, smaller bundle.
- **Skeletons that tell the truth** ([page.tsx:388-392](frontend/app/page.tsx:388)) — a `CardSkeleton` mirroring real card anatomy (avatar block, header lines, pill, tagline/description bars, footer badges, action pills), `min-h` matched to the real 304–311px card so the loading→loaded swap stops shifting (**a CLS improvement**), rendering 12. Drop `.glass` — 12 `backdrop-filter` surfaces during the LCP window is the most expensive thing on the page and buys nothing behind a placeholder. One composited `translateX` sweep, not `background-position`.
- **The verify stamp** — lives in `StatusPill` so the card grid and detail modal both get it from one place. On a transition into `verified`: pill `scale [1,1.06,1]`, the `ShieldCheck` icon lands from `rotate:-12, scale:0.6` on `SPRING_STAMP` (the one sanctioned overshoot — a rubber stamp rebounding off paper), plus one `aria-hidden` sage ring pulse that unmounts itself. ~600ms total.
- **Dead entries become filed, not faded** ([startup-card.tsx:278](frontend/components/startup-card.tsx:278)) — **drop the card-level `opacity-85`** (it was quietly reducing text contrast on exactly the cards a reader needs to read: an a11y win), keep `saturate-[0.6]`, add `grayscale` to the `HueAvatar` so the entry loses its colour identity, and add a rotated `FILED` stamp (`aria-hidden`, mono, `-rotate-6`). Hover lift drops to `y:-1` — filed cards are heavier.
- **Read-only status pill becomes informative** — the locked path becomes a real `<button>` opening the same `Popover` with the worded hint plus how verification works. Fixes Phase 9 item 6 for keyboard _and_ touch.
  > ⚠️ Nested Radix Tooltip+Popover on one trigger is the fiddliest thing here. If it misbehaves, go popover-only — don't spend an afternoon.
- **Hero reveal** — staged `.reveal-in` (opacity + `translateY(6px)`, 45ms steps): subhead, discovery bar, ledger line. **The `<h1>` does not animate** — it's the LCP element, and an element at `opacity:0` isn't counted as painted, so fading it in is a self-inflicted LCP regression. The headline is instantly there and the apparatus assembles beneath it.
- **The live dot waves once** — the Verified legend dot ([page.tsx:353](frontend/app/page.tsx:353)) and footer online dot get a `::after` ring scaling out, **capped at 3 iterations**. A greeting, not a heartbeat: no infinite animation, no battery cost. Unverified/Dead dots stay static — only the live one is alive.
- **Header reacts to scroll** — one `IntersectionObserver` on a 1px sentinel toggling `data-scrolled` (~12 lines; do **not** add a second `useScroll` rig). Background and border firm up; the tagline crossfades to a live ledger stamp. **No height change** — the header is in flow, and scroll-triggered shifts count toward CLS.
- **FilterBar finally signals state** ([filter-bar.tsx:54-105](frontend/components/filter-bar.tsx:54)) — off-default facets get `border-primary/50 bg-primary/10` + a dot, a per-facet clear-×, and "Clear all" under `AnimatePresence`; the count becomes a `CountUp`.
  > ⚠️ Use border + background only, **no `ring-*`/`box-shadow`** — `SelectTrigger` already spends box-shadow on its focus ring, and an active ring would collide. And do **not** tint the Status trigger sage/brick — that would leak reserved status hues into chrome.
  > ⚠️ The count sits inside `aria-live="polite"` ([:57](frontend/components/filter-bar.tsx:57)). An animating `CountUp` there makes a screen reader announce every frame. Put the animated digits in `aria-hidden` and give the live region a `sr-only` span with the plain final number.
- **`HomeSections` stop hard-cutting** ([page.tsx:382](frontend/app/page.tsx:382)) — `AnimatePresence` on opacity + y (no height animation), and its 12 mini-cards deal in per-strip.
- **Pagination gets the pill its docstring already promises** — [continuous-pagination.tsx:7-9](frontend/components/ui/continuous-pagination.tsx:7) claims a "sliding active pill (shared-layout)" that does not exist. Add `layoutId="pagination-pill"` on a **sibling span**, never on the button — `layoutId` on a focusable element writes an inline transparent box-shadow that clobbers its focus ring (the documented reason `.search-focus-ring` is hand-written).
- **Paper grain** — one layer, inside `sky-background.tsx`'s already-`aria-hidden` wrapper: an inline `feTurbulence` SVG data URI (~350 bytes of CSS, zero requests, rasterised once) at 3.5–5% opacity. **No `mix-blend-mode`** (forces a non-composited blend of the whole stacking context) and **never inside `.glass`** (it would be re-blurred by every sibling's backdrop-filter).
- **Offline banner becomes a fixed pill with a Retry** ([page.tsx:315-321](frontend/app/page.tsx:315)) — the current inline strip appears _after_ the failed fetch and shifts the whole page, a pure CLS hazard. A fixed bottom pill can't shift layout. The raw `uvicorn` command becomes dev-only — it's a dev instruction leaking to public visitors.
- **Admin accordion animates** ([admin-panel.tsx:221](frontend/components/admin-panel.tsx:221)) — height + opacity on `SPRING_SETTLE`. Height animation is acceptable **only here**: inside the dialog's own scroll container, admin-only, never on the LCP path. Chevrons rotate instead of swapping components ([admin-shared.tsx:47-51](frontend/components/admin-shared.tsx:47)), matching the discovery bar.
- **Sky breathing** — star twinkle via staggered CSS delays and a slow glow pulse on sun/moon, under `prefers-reduced-motion: no-preference`. The sky is the signature; this is the cheapest win in dark mode.

**Deliberately not doing** (flagged rather than built): confetti (new dep, torches the calm), konami code, cursor trails, mouse-tilt cards (perf cost across 24 backdrop-filtered surfaces + motion sickness), a marquee on "Just added" (an infinite animation contradicts the Micro-Delight Rule), and an ASCII `console.log` (ships to every user's devtools, says nothing).

## Phase 12 — Pagination: kill the cliff, don't paginate

**Measured, not assumed.** Payload at 1,292 rows: 950 KiB raw → **225 KiB gzipped (4.2x, not the "roughly 10x" claimed at [main.py:127](backend/app/main.py:127))** — 41.7% of the bytes are `description` prose, which doesn't compress well. `JSON.parse`: **1.02ms**. Memory: ~3–5MB against a ~50MB React baseline. None of these are the bottleneck.

**The bottleneck is Fuse, and it's linear in rows:** 22ms/term at 1,292 → 35ms at 2,500 → 70ms at 5,000 (desktop; ~4x on a mid-tier phone). The knee where search stops feeling instant is **~3,000 rows** — so `LIST_LIMIT_MAX = 5000` is already past the point where this architecture is pleasant.

**The urgent problem is the cliff, not the size.** [seeder.py:35](backend/app/seeder.py:35) caps a run at 500, so headroom from 1,292 to the 2,000 default is **1.4 seed runs**. When it trips, `fetchStartups()` sends no `limit`, so the body comes back short with HTTP 200 and no signal — while `/api/stats` does an unlimited `COUNT(*)`. The result is three counters and two truths on screen at once, with no error.

**Fix, six additive changes, no envelope and no new endpoint:**

- **Truncation is already detectable on the wire.** `loadAll` ([page.tsx:113](frontend/app/page.tsx:113)) already fetches `/api/stats` alongside the list, and `fetchStartups()` sends no filters — so `startups.length < stats.total` _is_ the signal. Derive it, and banner it honestly naming both numbers ("Showing 3,000 of 3,412 filings — search and filters only cover the 3,000 shown"). Condition on `online && !loading` so a failed list fetch doesn't make the banner lie. `main.py`'s `list[dict]` return type is untouched, so no risk to existing smoke assertions.
- **Move the ceiling to the measured knee**: `LIST_LIMIT_DEFAULT` 2000 → **3000** ([main.py:321](backend/app/main.py:321)). Takes headroom from 1.4 to 3.4 seed runs. `MAX` stays 5000 as an explicit opt-in.
- **Fix the two stale comments** — the 10x claim at :127, and the docstring at :341 which says the limit is "a growth ceiling" without saying what happens at the ceiling. Record the measured numbers and a `ponytail:` marker naming the upgrade path (SQLite FTS5 + bm25 for server-side _search_, **not** offset pagination) so the deferral shows up in `/ponytail-debt` instead of rotting.
- **Sink `pivoted` in SQL too** ([main.py:358](backend/app/main.py:358)) — the client sinks both `dead` and `pivoted` ([search.ts:69](frontend/lib/search.ts:69)), the SQL only sinks `dead`. Invisible today, but it becomes load-bearing the moment the `LIMIT` bites, because the `ORDER BY` then decides which rows survive truncation — tombstones should go first.
- **Fix the `page`/`currentPage` bug** (detailed in Phase 9).
- **Stop refetching 225 KiB on every status toggle.** `markVerified`/`markUnverified`/`markDead` already return the full updated row and [page.tsx:255](frontend/app/page.tsx:255) already patches it in optimistically; `loadAll` is only there for the counters. Add a `refreshCounts` helper (categories + stats) and use it at [:237](frontend/app/page.tsx:237) and [:257](frontend/app/page.tsx:257). **Keep `loadAll()` at [:485](frontend/app/page.tsx:485)** — a seed run inserts up to 500 unseen rows, so a full refetch is correct there.

**Documented in three existing places** (no new doc): the `main.py:341` docstring, the README API table row, and the README architecture section (where a newcomer forms the mental model — "the client holds everything, ceiling ~3,000 rows").

## Phase 13 — Merge the duplicate filings

10 name-groups are filed twice (Vue.js, Tailwind CSS, Stability AI, Motion, LangChain, GitLab, Fathom, Cal.com, Bun, Bird) — a directory whose job is "which startup is this?" showing identical cards twice.

**This is the only destructive step in the plan.** Sequence: take a timestamped DB backup via `sqlite3 .backup` (not `cp` — a live WAL copy can be torn) → run `backend/scripts/merge_duplicates.py` in **dry-run (the default)** → review the report → apply.

Merge rule: group by **normalised registrable domain**, keep the verified row plus the best URL/description, and merge the rest. That rule does the right thing automatically on the real data — `v2.vuejs.org`/`vuejs.org` and `about.gitlab.com/...`/`gitlab.com` share a registrable domain and merge; **Bird (`bird.com` vs `bird.co`) does not, so it is flagged for manual review rather than merged** — they may be genuinely different companies.

Also add the UI affordance regardless, because it's the honest one: when ≥2 filings share a name, render a muted "×2 filings" chip. Verify the seeder's upsert dedupe still holds so the class doesn't come back.

## Phase 14 — Cross-platform runner and CI

**Rewrite `scripts/verify.mjs`** (whose header comment already claims "cross-shell, no path games" and is neither):

- Resolve the interpreter per-platform — `Scripts/python.exe` on Windows, `bin/python` on POSIX — and honour a `PYTHON=` env override so CI can point at a bare interpreter with no venv.
- Spawn npm as `spawnSync("npm", ["test"], { cwd, shell: true })`. `shell: true` is required because Node refuses to spawn `.cmd`/`.bat` directly since the CVE-2024-27980 fix, and it's safe **here specifically** because the argv is two hardcoded literals and the only variable (the directory) travels as `cwd`, never as shell text. Never let a path into the string form of that call.
- Portable missing-venv message, and report `r.error` so an ENOENT doesn't print "exit null" and nothing else.

**Resolve the version contradiction — pin Node 24.** `README.md:32` advertises "Node.js 20+", but `npm test` **cannot run below Node 23** because the sort-check leg relies on native TypeScript type stripping. Node 24 is Active LTS and matches the dev machine; the alternatives (a version-sniffing `--experimental-strip-types` branch, or a build step for one 130-line test file) both cost more than they save. Add `engines: { node: ">=24" }` to both `package.json` files — Vercel/Netlify actually read the frontend one to select the build image. Python stays **3.11** everywhere to match the Dockerfile. Correct the README prerequisites and delete the now-false "There is no CI" note.

**`.github/workflows/ci.yml` (new)** — two jobs, three runners, proportionate to a solo project:

1. **test** on `[ubuntu-latest, windows-latest]`, `shell: bash` defaults so one set of steps covers both, Python 3.11 + Node 24 with pip/npm caching, **no venv in CI** (via `PYTHON=python`), then `npm test`. Plus `ruff check backend` on Linux only, using ruff's default rule set with no new config file.
   > ⚠️ `npm ci` in `frontend/` must run **before** `npm test`, not just before the build leg: `scripts/sort-check.ts` imports `frontend/lib/search.ts`, which imports `fuse.js` at module scope. This is the single most likely way a naive CI file fails.
   > Both non-npm suites are fully offline (smoke monkeypatches `httpx`, and `next build` is a client component with defaulted env), so CI needs no secrets.
2. **docker** — build `backend/Dockerfile` and poll `docker inspect` until the container's own `HEALTHCHECK` reports healthy, dumping health JSON and logs on failure. **This job earns its place: the image has never been built and its healthcheck has never executed**, so this is first-contact validation of a deploy artifact. Needs `ADMIN_TOKEN` set (the app refuses to start without it) and `VERIFY_AUTO_STALE_DAYS=0` so the container makes no outbound calls.

**Not adding** (overkill, flagged): a macOS runner, a Node version matrix, pytest, buildx/registry cache, `tsc --noEmit` (redundant — `frontend/tsconfig.json` has `noEmit: true` and `next build` doesn't ignore type errors, so it already runs a full `tsc`), Codecov, Dependabot, pre-commit, and `scripts/reflow-check.mjs` (hardcodes a Chrome path and needs a live dev server).

**Expected first-run surprises, in likelihood order:** the `npm ci` ordering above; an import failing on Linux's case-sensitive filesystem (exactly the bug the ubuntu leg exists to find); the timing-sensitive queue/rate-limit sleeps in `smoke.py` flaking on a loaded shared runner (raise the specific sleep, don't add a retry wrapper); and ruff finding something on first contact.
