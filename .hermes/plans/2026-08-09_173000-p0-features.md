# P0 Feature Batch — Status Signals, Filters/Sort, Similar Entries, Home Sections, Shareable URLs

> **For Hermes:** Use subagent-driven-development to implement task-by-task (fresh subagent per task, spec-compliance then code-quality review).

**Goal:** Ship the 7 P0 features from `docs/research-features-ux.md` — the quick-win, high-value additions proven by the analogues (TAAFT, YC directory, topstartups.io, Product Hunt) and user-voice evidence.

**Architecture:** All client-side, zero backend changes (additive, non-destructive, reversible — the user's standing rule). One filter-state object in `page.tsx` is the single source of truth; `lib/search.ts` gains extended pure filter/sort functions; URL params sync via `history.replaceState` (back-button-safe). Detail view = shadcn Dialog modal (no new route, keeps the one-pager identity). No schema/API/migration work.

**Tech Stack:** Next.js 16 (App Router, webpack dev), shadcn/ui (radix), Fuse.js, existing `lib/format.ts`/`lib/search.ts`.

## Design decisions (locked, from sequential-thinking pass)

| Decision | Choice | Why |
|---|---|---|
| Detail form factor | Modal Dialog, not `/startup/[id]` route | One-pager identity; no prerender/routing complexity; Escape/keyboard a11y free |
| Filtering | Client-side (`lib/search.ts`), backend untouched | All data already loaded; zero API/migration churn |
| URL sync | `history.replaceState` on every change, params read once on mount (window guard) | Back-button-safe; no history spam (TAAFT launch-feedback lesson) |
| Default sort | Stars desc ("Top") | Relevance signal users asked for ("which listings matter"); freshness served by the Just-added section |
| Similar block | Same `category`, exclude self, up to 4, clickable → swaps modal content | Cheap, grounded in "alternatives" mental model |
| Home sections | Render only when no filters active | Keeps filtered views focused |

```ts
// lib/format.ts
export function formatDate(iso: string | null): string {
  if (!iso) return "—";
  const d = new Date(iso);
  if (Number.isNaN(d.getTime())) return "—";
  return d.toLocaleDateString("en-US", { year: "numeric", month: "short", day: "numeric" });
}
```
```ts
// lib/search.ts additions
export type SortKey = "top" | "newest" | "verified" | "name" | "founded";
export function sortStartups(startups: Startup[], key: SortKey = "top"): Startup[] {
  const arr = [...startups];
  const by = (f: (s: Startup) => number | string) =>
    arr.sort((a, b) => (f(b) as number) - (f(a) as number) || (b.stars ?? 0) - (a.stars ?? 0));
  switch (key) {
    case "newest": return by((s) => new Date(s.created_at ?? 0).getTime());
    case "verified": return by((s) => new Date(s.verified_at ?? 0).getTime());
    case "name": return [...startups].sort((a, b) => a.name.localeCompare(b.name));
    case "founded": return by((s) => new Date(s.founded ?? 0).getTime());
    default: return by((s) => s.stars ?? 0);
  }
}
export interface Filters { q?: string; category?: string; year?: string; status?: string; }
export function filterStartups(startups: Startup[], f: Filters): Startup[] { /* existing AND-fuse on q + category; add: year → (s.founded ?? "").startsWith(f.year); status → map as specced */ }
```

## Risks / tradeoffs

- Client-side filtering at 1,259 entries: fine (Fuse on ~1.3k strings is instant); revisit if the directory grows 10×.
- Modal detail means no deep-linkable per-startup URLs — accepted for the one-pager identity (P2 could add real routes).
- Home strips add vertical space when unfiltered — keep them compact (one row each, 4 items) to preserve the warm-minimal feel.
- `replaceState` URL sync: ensures back button exits the app cleanly instead of stepping through every filter change — this is deliberate (TAAFT back-button complaint).
